# 金融文档智能问答助手

## 1. 项目介绍

**财务文档智能问答助手** 是一个基于检索增强生成（Retrieval-Augmented Generation, RAG）的智能问答系统，专为财务年报、财报等专业文档设计。用户可上传 PDF、DOCX、TXT 格式的财务文件，系统自动解析文档内容，并通过自然语言问答的方式，提供准确、严谨的回答，同时附上答案所依据的文档片段和来源，显著提升答案的可信度。

系统提供友好的 Web 界面（基于 Gradio），支持多知识库管理、文档上传、自动创建知识库、流式对话、会话记忆、引用来源展示等功能，适用于企业财务分析、投资研究、审计辅助等场景。

## 2. 需求背景

### 2.1 痛点分析

- **财务文档体量大**：上市公司年报动辄数百页，人工阅读耗时耗力，难以快速提取关键指标。
- **专业术语密集**：财务指标、会计准则、报表注释等需要精准理解，通用大模型容易产生幻觉。
- **数据时效性要求高**：通用大模型训练数据滞后，无法回答最新财报问题。
- **信息分散**：同一份年报中的关键数据可能分布在正文、表格、附注中，快速定位困难。
- **多文档管理复杂**：用户需要同时维护不同公司、不同年份的财报，并进行交叉查询。
- **答案可追溯性弱**：纯文本答案缺乏引用，难以验证来源，降低信任度。

### 2.2 解决目标

- 构建一个**本地化、可私有部署**的财务问答系统，保护数据安全。
- 实现对财务文档的**自动化解析与向量化存储**，支持语义检索与关键词检索的混合检索。
- 提供**多知识库管理**能力，用户可独立管理不同公司或年份的文档集合。
- 实现**基于检索增强的问答**，答案必须源自文档内容，并展示引用来源。
- 支持**多轮对话与上下文记忆**，能够结合历史信息回答追问。
- **简化操作**：用户输入知识库名称即可自动创建，无需预先定义。

### 3.3 关键模块详解

#### 3.3.1 文档处理模块 (`document_loader.py`)

- **功能**：加载并切分文档，支持 PDF、DOCX、TXT。
- **流程**：
  1. 根据文件扩展名选择解析器（PDF 使用专用解析器，其他使用 `UnstructuredFileLoader`）。
  2. PDF 解析时，使用 PyMuPDF 提取文本和表格（`page.find_tables()` 转换为 Pandas DataFrame 后拼接）。
  3. 使用 `RecursiveCharacterTextSplitter` 将文档切分为 chunks，块大小 1000 字符，重叠 200 字符。
  4. 元数据中包含 `source`（原始文件名）、`page`（页码）、`type`。
- **输出**：LangChain `Document` 对象列表。

#### 3.3.2 向量存储模块 (`vector_store.py`)

- **设计模式**：单例模式 `OptimizedChroma`，全局共享 Chroma 客户端。
- **特性**：
  - 每个知识库对应 Chroma 中的一个独立 Collection（名称 = kb_id）。
  - 嵌入模型使用 DashScope `text-embedding-v3`。
  - 支持 HNSW 索引参数优化（余弦距离、M=8、ef_construction=64、ef=32）。
  - `add_documents`：批量添加文档切片并自动持久化。
  - `delete_kb`：删除整个 Collection。
- **持久化**：Chroma 0.4.x 自动持久化，无需手动调用 `persist()`。

#### 3.3.3 知识库管理模块 (`mysql_db.py`)

- 存储两张表：
  - `knowledge_base`：id (UUID), name, create_time
  - `documents`：id, kb_id, filename (原始文件名), upload_time
- 提供增删查接口，确保知识库与文档的关联关系。

#### 3.3.4 RAG 检索与生成链 (`rag_chain.py`)

**混合检索器**：

- 使用 `EnsembleRetriever` 组合：
  - Chroma 向量检索（权重 0.7，返回 5 个文档）
  - BM25 关键词检索（权重 0.3，返回 5 个文档）
- 检索结果通过 Redis 缓存（key 为 `rag:{kb_id}:{query_md5}`，TTL=1 小时）。

**Prompt 设计**：

python

```
system: 你是专业财务分析师，仅依据提供的文档回答问题。
文档片段：{context}
要求：准确、严谨、简洁，无信息时明确说明

{chat_history}  # 多轮对话历史占位符

human: {input}
```



**对话记忆**：

- 使用 `RunnableWithMessageHistory` 包装基础链。
- 历史存储：`RedisChatMessageHistory`，TTL=7 天。
- 窗口记忆：保留最近 6 条对话（`ConversationBufferWindowMemory`）。

**引用来源**：

- `chat_with_citations` 方法返回答案生成器和检索到的文档片段列表。
- 每个片段包含：截取内容（前200字符）、原始文件名、页码。
- 答案生成完成后，在末尾附加 Markdown 格式的引用块。

#### 3.3.5 对话管理模块 (`chat_manager.py`)

- 提供统一的 `get_history(session_id)` 和 `get_memory(session_id)` 接口。
- 全局单例 `chat_manager` 供 RAG 链调用。

#### 3.3.6 前端交互模块 (`app.py`)

**主要功能**：

- 知识库选择（支持手动输入 + 下拉选择，`allow_custom_value=True`）
- 文档上传（若知识库不存在则自动创建）
- 知识库删除（同时删除向量库和 MySQL 记录）
- 刷新知识库列表（手动按钮 + 页面加载自动刷新）
- 多轮对话聊天框（流式输出 + 引用来源）
- 清空对话

**事件绑定**：

- 上传后自动刷新下拉列表。
- 删除后自动刷新下拉列表。
- 页面加载时（`demo.load`）刷新下拉列表。
- 提交问题后调用 `chat_with_citations`，流式显示答案，最后追加引用。

### 3.4 工作流程

#### 文档上传流程

1. 用户输入/选择知识库名称，上传文件。
2. 后端检查知识库是否存在，若不存在则自动创建（生成 UUID，插入 MySQL）。
3. 调用 `DocumentProcessor.load_file` 解析并切分文档，元数据中记录原始文件名。
4. 调用 `vector_store.add_documents` 将切片向量化并存入 Chroma Collection。
5. 在 MySQL `documents` 表中记录该文档（原始文件名）。
6. 前端刷新知识库下拉框。

#### 问答流程

1. 用户选择知识库，输入问题。
2. 后端根据 `kb_name` 获取 `kb_id`。
3. 调用 `rag_chain.retrieve`：
   - 检查 Redis 缓存，若有则直接返回上下文。
   - 否则构建混合检索器，执行检索，合并结果后存入缓存。
4. 调用 `rag_chain.chat_with_citations`：
   - 获取检索到的文档片段列表（用于引用）。
   - 将问题、上下文、会话历史（从 Redis 读取）组装成 prompt。
   - 调用 DashScope LLM 生成答案（流式）。
5. 前端逐 token 显示答案。
6. 答案生成完毕后，将引用来源（文件名、页码、片段内容）以 Markdown 格式追加到答案末尾。
7. 新产生的对话记录自动存入 Redis 历史。

### 3.6 性能优化亮点

- **混合检索**：结合语义与关键词，避免单纯向量检索遗漏精确匹配。
- **检索结果缓存**：相同问题 1 小时内复用上下文，减少 LLM 调用和检索开销。
- **流式输出**：提升用户体验，避免长时间等待。
- **窗口记忆**：保留最近 6 条对话，控制 token 消耗。
- **索引优化**：手动调整 HNSW 参数，提高检索速度和精度。
- **自动创建知识库**：简化用户操作，提升易用性。

## 4. 使用示例

1. 启动服务后访问 `http://127.0.0.1:7860`。
2. 在“选择知识库”中输入“厦门灿坤2019年报”（若不存在会自动创建）。
3. 上传 `厦门灿坤2019年年度报告.pdf`，等待解析完成。
4. 在右侧聊天框提问：“公司2019年归属于上市公司股东的净利润是多少？相比2018年增长了多少？”
5. 系统流式返回答案，最后显示：
   - 答案：105,233,212.02 元，同比增长 789.42%。
   - 引用来源：文件名、页码、相关原文片段（含表格数据）。
6. 可继续追问：“营业收入是多少？”系统结合上文回答。
